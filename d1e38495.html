    • 客户端工程复盘
      • AI辅助客户端研发
        • Agent评测：任务完成率不能代表工程收益
        • 上下文装配：更长 Prompt 不能替代可追溯 Grounding
        • 写入回滚：文件快照不能替代跨编辑器事务
        • 取消语义：Abort Signal 不能撤销已经发生的副作用
        • 工具权限：Tool Schema 不是执行授权
        • 生成资产：预览可见不等于可以进入内容库
        • 能力边界：模型负责提出变更，不负责证明变更正确
      • UE生命周期与异步边界
        • 动态组件：NetMode不等于Actor的本地角色
        • 原生回调：进程单例解决入口，不解决结果属于谁
        • 反射重置：把UPROPERTY拷回模板不等于恢复Actor
        • 后台写盘：线程安全队列不等于可关闭管线
        • 延迟Spawn：FinishSpawning之前不能发布半成品Actor
        • 异步资源槽：Tag能去重，不能拒绝旧回调
        • 归档异步：GC保活不等于工作线程可以操作UObject
        • 攻击窗口：Timer只能调度，不能定义一次技能事务
        • 池化Actor：局部循环Timer会把上一世带进下一世
        • 看门狗线程：只能报告超时，不能跨线程修改VM
        • 编辑器模块卸载：解绑委托还不够，注册工厂也必须撤销

        • Prefab覆盖：没有基线版本的 Diff 只是一次猜测
        • 二进制兼容：格式能解析不代表可以安全回退
        • 保存快照：后台保存不能重读活对象树
        • 内容安全：摘要、来源信任和加密不能互相替代
        • 切换关卡：Load 与 Unload 必须组成可补偿事务

        • 多文件保存：Manifest 最后写不等于真正原子
        • 对象身份：ObjectId 不是跨 VM 的全局身份

        • 相机身份：逻辑 Camera 不等于 ViewTarget Actor

        • Actor迁移：先抽离真相，再替换运行时表示
        • UGC客户端架构面试复盘：从创作模型到运行时边界

        • 生命周期归属：Subsystem 可全局访问不等于它活得够久

        • 角色对称：Client 与 DS 应共享契约，不应共享启动时序

客户端工程决策手册：从问题到契约与证据

自动关联目录：客户端工程决策手册：从问题到契约与证据

这不是另一篇架构总览，而是一张入口表：先把症状归类，再找到必须建立的契约和可以证明结果的证据。具体实现、反例和取舍仍以链接文章为准。

一、先定位问题属于哪一层

客户端问题
├─ 数据不一致：谁是真相？身份和版本是什么？
├─ 生命周期错位：事实应该活过 Session、World、Actor 还是一次请求？
├─ 异步竞态：回调回来时，它是否仍有提交权？
├─ 线程边界：对象存活、数据同步和业务有效性是否被混为一谈？
├─ 半次变更：哪些写入必须作为一次事务提交？
├─ 多端分歧：Client、DS、编辑器分别拥有哪部分权威？
├─ 规模失控：是否把逻辑对象过早物化成 Actor、组件或重资源？
├─ 结果不可证：用什么确定性证据说明功能、性能和恢复正确？
└─ AI 自动化：模型能提出什么，宿主允许什么，谁负责验收？

不要从“该用哪个 UE 类”开始。先回答真相、身份、生命周期、提交边界、权威和证据，再选择 Actor、Subsystem、GAS、Mass、ISM/HISM、Slate 或工具框架。

四、设计前检查单

4.1 真相与身份

  • 哪份数据是创作事实、运行时权威、派生索引和表现投影？
  • ID 在跨 World、跨进程、对象复用和重建后是否仍唯一？
  • 引用是否携带 Revision、Domain 或 Generation，而不是只存裸指针和名字？
  • 缓存、Manifest、分类表能否从权威事实重建？
  • 批量资源解析是否为每个输入返回状态，并区分 Required 与 Optional？
  • 资产目录规则是否使用规范包名和目录段，而不是字符串子串？
  • 资产别名冲突是否显式返回 Ambiguous，解析结果是否按值持有且不受后续查询影响？

参考：派生索引、资产身份、跨语言合约。

4.2 生命周期与异步

  • 事实应归 GameInstance、World、Actor、组件、播放会话还是一次操作？
  • Travel、PIE 重启、对象池复用、热重载和断线重连会改变哪个代次？
  • 每个异步结果提交前是否重验需求、所有者、Revision 和运行角色？
  • Cancel、Timeout、Failed、Unknown Outcome 和 Rolled Back 是否是不同状态？
  • UObject 保活、工作线程访问许可和结果提交权是否分别证明？
  • 后台消费者能否被唤醒，并在关闭时明确 Drain 或 Abort 后 Join？
  • 模块、页面或 World 结束时，委托、Timer、Registry 和原生请求是否失效？
  • 循环 Timer 是否有可撤销的成员句柄，并在回池、停用与 EndPlay 时关闭？
  • 回池后的同一 UObject 是否增加 ReuseGeneration，并拒绝上一代回调？
  • 属性恢复完成后，是否还验证外部注册、物理、网络和异步任务已经静默？
  • 软资源预热是否区分 Loading、Ready、Failed 与 Closed，而不是只返回空对象？
  • 同一个 Tag 被替换时，旧请求是否因 Generation 变化而失去提交权？
  • Deferred Actor 是否在 Finish 和不变量校验前保持未发布，复制配置是否在正确阶段冻结？
  • 异步物理查询是否绑定 Attempt、ContextGeneration 和发起时参数快照？
  • AnimNotifyState 是否只保存配置，来源 Mesh、播放器、生成组件和清理权是否属于逐播放绑定？

参考：生命周期归属、归档异步、后台写盘、编辑器模块卸载、原生回调、攻击窗口、池化Timer、反射重置、软类预热、异步资源槽、延迟Spawn。

4.3 UE 表示选择

  • 该对象必须拥有 Actor 生命周期、网络通道、独立碰撞和脚本宿主吗？
  • 只有可见、可交互或进入相关性的对象，是否可以按需物化？
  • ISM/HISM、合批或代理表示失去了哪些编辑、碰撞、材质和变换能力？
  • DS 是否需要渲染资产，Client 是否被迫承载只属于权威模拟的数据？
  • 动态组件创建是否分别判断 NetMode、Authority、Local Control 和复制来源，并支持重复 Reconcile？
  • Spline、射线、碰撞与渲染几何的输入是否携带空间语义，并只转换一次？
  • 可编辑特效曲线是否先排序、去歧义和编译，并只让活跃绑定进入 Tick？
  • 临时物理变更是否按 Body 和调用方持有 Lease，释放时只撤销自己的意图？

参考：网格合批、碰撞表示、跨目标降级、动态组件、SplineMesh。

4.4 网络与玩法权威

  • 客户端发送的是意图、预测还是事实？DS 会重新证明哪些资格？
  • 状态、瞬时事件、命令和处理回执是否使用了不同通道？
  • 晚加入、重连、丢包、乱序和所有权迁移后如何恢复？
  • 视觉、动画和音频能否被纠正或取消，而不反向决定玩法结果？
  • 路由、每连接相关性、调度优先级和实际传输预算是否分层？
  • 连接离开兴趣集合时，是否误用了 TearOff 或全局 Destroy？
  • 数量限流是否还验证了 Initial Channel、Bits、CPU 和最大等待年龄？
  • Fast Array 承载的是可恢复状态，还是必须逐次消费的业务事件？

参考：交互资格、物理所有权、复制路由、复制预算、组相关性、FastArray。

4.5 性能与证据

  • 成本是否按 Decode、Spawn、初始化、Tick、复制、渲染和回收阶段拆开？
  • 预算约束的是任务数量，还是主线程时间、队列年龄和不可抢占长尾？
  • 工作集是否绑定空间候选、活跃对象和变化集合，而不是每帧全量扫描？
  • 指标是否包含 P95/P99、连续慢帧、阶段身份和 Client/DS 真实负载？
  • 音频等数量预算是否先预留再启动，并保证有效 Lease 数与 Used 完全一致？

参考：主线程预算、集中调度、性能基准。

4.6 AI 辅助开发

  • 模型输出是候选、假设、观察还是确定性证据？
  • 上下文事实是否带来源、版本、信任级别、有效期和数据策略？
  • 工具权限是否绑定资源、Effect、次数、预算和过期时间？
  • 变更是否经过 Schema、编译、Client/DS 运行、性能和人工审批门禁？
  • 评测是否记录返工、审查、回滚、取消、未知结果和资源成本？

参考：能力边界、上下文装配、Agent评测。

六、判断方案是否真的更好

一个方案只有同时回答下面五个问题，才算架构改进，而不是换了一组类名：

  1. 守住了什么不变量：身份唯一、权威唯一、创作数据不被试玩污染，或同一 Revision 的多目标制品不互相覆盖。
  2. 缩小了什么工作集：从全部对象缩到空间候选、活跃集合、变化集合或明确相关性。
  3. 把失败变成了什么状态：可重试、可补偿、结果未知、需要对账，还是必须人工裁决。
  4. 付出了什么成本：更多元数据、状态机、存储、延迟、工具复杂度或内容约束。
  5. 拿什么证明：静态契约、单元测试、真实 Client/DS 运行、故障注入、平台构建、性能分位数和人工审查。

如果回答只能落在“更优雅”“更通用”或“模型认为正确”，就还没有完成工程决策。
