网络层的职责

网络层做两件事：

  1. 转发（Forwarding）：分组到达路由器时，查表决定从哪个口出去。是单台设备的本地动作
  2. 路由（Routing）：全网所有路由器协同计算转发表。是全局的、分布式的规划过程

转发 = 按地图走；路由 = 画地图。

网络层的服务模型是 尽力而为（best-effort）：不保证送达、不保证按序、不保证不重复、不保证延迟。可靠由传输层补——这是端到端原则的直接体现。

IPv4 数据报格式

 0        4        8            16      19      24        32
┌────────┬────────┬──────────────┬────────┬─────────────────┐
│ 版本(4) │ 头长(4) │  服务类型 TOS │       总长度(16)       │
├────────┴────────┼──────────────┼─────────────────────────┤
│     标识(16)     │ 标志(3) │    片偏移(13)              │
├──────────────────┼─────────┼──────────┬──────────────────┤
│    生存时间 TTL   │  协议(8) │        头部校验和(16)      │
├──────────────────┴─────────┴──────────┴──────────────────┤
│                    源 IP 地址(32)                          │
├──────────────────────────────────────────────────────────┤
│                   目的 IP 地址(32)                         │
├──────────────────────────────────────────────────────────┤
│              选项（若有）+ 填充                            │
├──────────────────────────────────────────────────────────┤
│                        数据                                │
└──────────────────────────────────────────────────────────┘

典型头部 20 字节（无选项时，头长字段为 5，单位是 32 bit 字）。

字段作用
版本IPv4 = 4
头长 IHL头部占多少个 32-bit 字，最小 5（20 字节）
TOS/DSCP服务类型，用于 QoS 区分服务
总长度头 + 数据，最大 65535
标识/标志/片偏移分片与重组用
TTL每过一跳减 1，到 0 就丢弃。防止路由环路导致无限循环
协议上层协议号：6=TCP、17=UDP、1=ICMP
头部校验和只校验头部（数据部分由传输层校验）。每跳都要重算，因为 TTL 变了

TTL 的妙用：traceroute 就是靠发 TTL=1,2,3... 的包，让沿途路由器依次回 ICMP 超时，从而探测出路径。

IPv4 地址

32 bit，点分十进制表示，如 192.168.1.1。

分类编址（早期，已废弃但要知道）

类前缀网络位/主机位范围
A08 / 241.0.0.0 ~ 126.255.255.255
B1016 / 16128.0.0.0 ~ 191.255.255.255
C11024 / 8192.0.0.0 ~ 223.255.255.255
D1110组播224.0.0.0 ~ 239.255.255.255
E1111保留240.0.0.0 ~

问题：C 类只有 254 个主机，B 类有 65534 个。一个需要 300 个地址的组织只能拿 B 类，浪费 65000 个。这是地址枯竭的重要原因。

CIDR（无类域间路由）

现代方案。地址写成 a.b.c.d/n，/n 表示前 n 位是网络前缀。

192.168.1.0/24   → 前 24 位是网络号，后 8 位是主机号 → 254 个可用主机
10.0.0.0/8       → 16777214 个主机
192.168.1.128/25 → 126 个主机

计算网络地址的规则：IP 与子网掩码按位与。

IP:        192.168.1.130  = 11000000.10101000.00000001.10000010
掩码 /25:  255.255.255.128= 11111111.11111111.11111111.10000000
AND:       192.168.1.128  ← 网络地址
广播地址:  192.168.1.255  ← 主机位全 1
可用主机:  192.168.1.129 ~ 192.168.1.254 （126 个）

可用主机数 =2(32−n)−22^{(32-n)} - 22(32−n)−2（减去网络地址和广播地址）。

子网划分

把一个大网络切成若干小网络：

公司拿到 192.168.1.0/24，要分 4 个部门各约 60 台主机

需要 6 位主机位（2^6-2 = 62 ≥ 60）
→ 每个子网 /26（主机位 6 位）
→ 可切出 4 个 /26：
   192.168.1.0/26     (1~62)
   192.168.1.64/26    (65~126)
   192.168.1.128/26   (129~190)
   192.168.1.192/26   (193~254)

私有地址与特殊地址

RFC 1918 私有地址（内网用，不出现在公网）：

10.0.0.0/8         (10.0.0.0 ~ 10.255.255.255)
172.16.0.0/12      (172.16.0.0 ~ 172.31.255.255)
192.168.0.0/16     (192.168.0.0 ~ 192.168.255.255)

其他特殊地址：

地址含义
127.0.0.0/8环回（localhost）
0.0.0.0本网络的本主机 / 默认路由
255.255.255.255本地广播
169.254.0.0/16链路本地（DHCP 失败时自动分配，APIPA）

IPv4 地址枯竭

32 bit 约 43 亿个地址，2011 年 IANA 最后一块 /8 分配完毕。缓解手段按时间顺序：

  1. CIDR：提高分配效率
  2. NAT：多台机器共用一个公网 IP（最有效，也最破坏端到端原则）
  3. IPv6：根本解决方案

NAT（网络地址转换）

NAT 让整个内网共享一个公网 IP。

工作原理

内网机器 192.168.1.100:5000 访问 8.8.8.8:53

出方向:  源 192.168.1.100:5000  →  替换为 公网IP:60001
入方向:  目的 公网IP:60001       →  替换回 192.168.1.100:5000

路由器维护一张 NAT 转换表：

内网地址:端口外网端口
192.168.1.100:500060001
192.168.1.101:500060002

NAPT / PAT（端口复用）是关键：靠端口区分不同内网主机，所以叫"IP + 端口"的转换。

NAT 的问题

破坏端到端原则：外网无法主动连接内网主机（NAT 表里没有对应条目）。

后果：

  • P2P 应用（BT、视频通话）需要 NAT 穿透（STUN/TURN/ICE）
  • 自建服务要做端口映射（手动配 DNAT）
  • IPv6 的普及动机之一

NAT 类型（影响穿透难度）

类型行为穿透难度
全锥型（Full Cone）一旦建立映射，任何外网主机都能从该端口连进来最容易
受限锥型只允许之前通信过的 IP中等
端口受限锥型只允许之前通信过的 IP:端口较难
对称型（Symmetric）每个目的地址一个映射最难，几乎必须 TURN 中转

ICMP

IP 的"控制协议"，用于报告错误和传递查询，不承载用户数据。

类型用途
0 / 8Echo Reply / Request（ping）
3目的不可达（细分：网络不可达、主机不可达、端口不可达…）
11TTL 超时（traceroute 用）
5重定向（告诉主机有更好的路由）
12参数错误

ping 的工作：发 ICMP Echo Request，收到 Reply 则通。输出里能看到 RTT 和 TTL（用初始 TTL 减剩余 TTL 可以估算跳数）。

traceroute 的工作：

发 TTL=1 的包 → 第 1 跳路由器回 ICMP TTL 超时 → 得到第 1 跳
发 TTL=2 的包 → 第 2 跳路由器回超时 → 得到第 2 跳
... 直到到达目的（回 ICMP 端口不可达 = 到达）

路由算法

两大类

链路状态（Link State）距离向量（Distance Vector）
知道的信息全网拓扑只知道邻居的距离
算法Dijkstra 求最短路径Bellman-Ford 分布式迭代
收敛快慢，可能计数到无穷
报文洪泛链路状态通告（LSA）周期性与邻居交换距离表
代表OSPF、IS-ISRIP、BGP（路径向量）
规模适合同一自治系统内适合小规模 / 跨域

OSPF（Open Shortest Path First）

  • 自治系统（AS）内部的路由协议（IGP）
  • 链路状态 + Dijkstra
  • 代价通常基于带宽：cost = 参考带宽 / 接口带宽
  • 支持**区域（Area）**分层，把大网络切成骨干区 + 若干非骨干区，减少 LSA 洪泛范围

BGP（Border Gateway Protocol）

  • 自治系统之间的路由协议（EGP）——互联网的 glue
  • 路径向量：通告的不只是距离，还有完整的 AS 路径（AS1 → AS3 → AS7）
  • 选路基于策略（商业关系、费用），不是最短跳数
  • 互联网的核心路由表有 90 万+ 条

为什么互联网用 BGP 而不是最短路径？因为不同运营商是竞争关系，"最短"不是他们的目标，"不经过竞争对手的网"或者"走我们买了 transit 的那家"才是。BGP 提供的是策略表达能力。

转发表查找

路由器收到包后：最长前缀匹配（Longest Prefix Match）。

转发表:
  192.168.1.0/24   → 端口 1
  192.168.1.128/25 → 端口 2
  0.0.0.0/0        → 端口 3（默认路由）

目的 192.168.1.200：
  匹配 /24 ✓
  匹配 /25 ✓   ← 前缀更长，选它 → 端口 2

实现上用 TCAM（三态内容寻址存储器）做硬件级并行匹配，一个时钟周期出结果。

DHCP

主机接入网络时自动获取 IP、子网掩码、默认网关、DNS 服务器。

1. 客户端广播 DHCP Discover    "我需要一个 IP"
2. 服务器回应 DHCP Offer       "给你 192.168.1.100"
3. 客户端广播 DHCP Request     "我要 192.168.1.100"
4. 服务器回 DHCP ACK           "成交，租期 8 小时"

DORA 四步。因为客户端还没有 IP，所以前两步是广播（链路层广播 ff:ff:ff:ff:ff:ff，IP 广播 255.255.255.255）。

租期过半要续约（发 DHCP Request 单播给服务器）。

IP 分片与重组

MTU：链路层一帧能承载的最大数据（以太网 1500 字节）。

IP 包大于出接口 MTU 时，路由器分片，目的主机重组。

原始: [IP头][数据 3000 字节]     MTU = 1500
                                 每片最多 1480 字节数据

片1: [IP头 MF=1, offset=0][1480 字节]
片2: [IP头 MF=1, offset=185][1480 字节]   ← offset 单位是 8 字节
片3: [IP头 MF=0, offset=370][40 字节]     ← MF=0 表示最后一片

为什么尽量避免分片：

  • 任一片丢失 → 整个包作废（IP 层不重传）
  • 重组消耗目的主机资源，且有超时
  • 某些防火墙会丢弃分片包（安全考虑）

TCP 的解法：握手时协商 MSS = MTU - IP头 - TCP头（通常 1460），从源头保证不分片。

路径 MTU 发现（PMTUD）：发 DF（Don't Fragment）标志的包，路由器无法承载时回 ICMP "需要分片"，据此逐步降低发包大小。但 ICMP 常被防火墙拦，导致 PMTU 黑洞——症状是"小包通，大包卡"。

IPv6

主要变化

方面IPv4IPv6
地址长度32 bit128 bit
表示法点分十进制冒号十六进制 2001:db8::1
头部20B，可变，有选项固定 40B，选项用扩展头
分片路由器和主机都能分只有源主机能分
校验和有（头部）无（交给上层）
ARP有被 NDP（邻居发现）替代
QoSTOS流标签（Flow Label）
地址配置DHCPSLAAC 无状态自动配置
IPSec可选设计上内建（实际仍可选）

为什么这样改

  • 固定 40 字节头部：路由器处理更快，不用解析变长选项
  • 去掉头部校验和：TTL 在 IPv6 里改叫 Hop Limit，仍然每跳递减，但既然传输层已经有了校验和，再算一次是纯浪费
  • 只有源端分片：路由器不再承担分片开销
  • SLAAC：主机根据链路前缀 + 自己的 MAC（或随机生成）自动生成地址，插上网线就能通信

过渡技术

IPv6 和 IPv4 不兼容，需要过渡：

  • 双栈：主机同时跑 v4 和 v6
  • 隧道：6in4、6to4、Teredo（把 v6 包封装在 v4 里）
  • NAT64/DNS64：v6 -only 主机访问 v4 资源

常见坑

  • 子网算错：/24 有 254 个可用主机，不是 256。/31 只有 2 个地址（点对点链路专用）
  • NAT 下对外服务不通：忘了配端口映射
  • PMTU 黑洞：VPN 后大文件传不动，小网页正常。解法是 MSS Clamping（在 TCP 握手时改写 MSS）
  • ICMP 全禁：会导致 PMTUD 失效、traceroute 失效，还会掩盖真实的网络问题。至少要放行"需要分片"和"TTL 超时"
  • IPv6 优先级：现代 OS 默认优先 IPv6，如果 v6 不通会导致 5 秒级的连接延迟（Happy Eyeballs 算法缓解了这个问题）
  • 路由环路：配错静态路由会导致包在两台路由器间来回传，靠 TTL 兜底。现象是 ping 显示 TTL expired in transit
