NavMesh

Unreal Engine, AI, NavMesh 2025-08-10 2026-10-10 1076 字

自动关联目录：NavMesh

NavMesh 把"能不能走"预先烘焙成一张多边形网格，寻路时在这张图上做 A*，而不是在原始几何体上算。这是所有"能寻路"的前提。

生成方式

方式特点
静态烘焙编辑器生成，运行时零成本
动态运行时生成支持程序生成关卡，成本高
动态修改（Nav Modifier / Nav Link）局部改变可达性，最常用

绝大多数项目用静态烘焙 + 少量动态修改。

核心概念

概念说明
ANavMeshBoundsVolume划定烘焙范围
UNavArea区域类型与代价（默认行走、跳跃、门、危险区）
NavAreaFlag / FixedCostEntering给某类区域加通行代价
ANavModifierVolume修改区域内代价或标记为不可走
UNavLinkComponent / ANavLinkProxy连接断开的区域（跳跃点、梯子）
UNavFilter寻路时用哪套代价规则
RecastNavMesh实际使用的导航数据（Recast）

代价（Cost）是 AI 行为调优最有效的旋钮：不想让 AI 走某条路，不一定要封死，把代价调高即可，路径自然会绕开。

常用设置

设置作用
Cell Size / Cell Height体素精度，越小越准越慢
Agent Radius / Height代理尺寸，决定能钻多窄的缝
Agent Max Slope能爬多陡
Agent Max Step Height能跨多高
Runtime Generation是否运行时重建

多尺寸单位要多个 NavMesh：体型差异大（人/车/巨兽）应配置不同的 SupportedAgents，而不是共用一套参数。

寻路接口

UNavigationSystemV1* NavSys =
    FNavigationSystem::GetCurrent<UNavigationSystemV1>(World);

FPathFindingQuery Query(Owner, *NavData, Start, End);
Query.SetAllowPartialPaths(bPartial);
auto Result = NavSys->FindPathSync(Query);
接口用途
FindPathSync同步寻路（简单但会卡帧）
RequestPathMove / UPathFollowingComponent通过组件移动
AIController::MoveToLocation最常用封装
NavSys->ProjectPointToNavigation把点投影到导航面上
IsValidPathPoint / TestPathSync判断可达

异步寻路：大量 AI 同时寻路时要用异步请求，否则主线程会卡。引擎提供 FNavPathSharedPtr 与异步任务接口。

动态障碍

手段说明
NavModifierVolume提前摆好的区域
组件 DynamicObstacle（UNavRelevantComponent）移动物体阻挡
Runtime Generation: Dynamic运行时重建局部瓦片（有成本）
NavLinkProxy手动补足连接

动态重建是最贵的操作，只在必要时用，且限制重建范围（瓦片大小）。

常见坑

坑说明
没有 NavMeshBoundsVolume没烘焙出任何东西
目标点不在导航面上寻路失败；先 ProjectPointToNavigation
Agent 尺寸与实际角色不符卡墙角、钻不过去
大量 AI 同时 FindPathSync主线程卡顿
动态障碍每帧改频繁重建，性能崩溃
只用一套 NavMesh 覆盖所有体型要么卡住要么穿墙
