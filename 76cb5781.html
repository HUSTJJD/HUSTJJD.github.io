UAttributeSet

Unreal Engine, GamePlay, Game Ability System 2025-08-10 2026-10-10 2478 字

自动关联目录：UAttributeSet

属性集定义、管理、复制一个或多个属性值。属性是"在游戏机制中具有特定含义的数值"：可以代表游戏资源（Health）、影响其他规则的参考值（Base Attack Power），也可以代表无状态量（Applied Damage）。

一句话定位：AttributeSet 是 GAS 的数据层，GE 是修改它的唯一正当途径，Tag 是描述它的元数据。

基本写法

UCLASS()
class UMyAttributeSet : public UAttributeSet
{
    GENERATED_BODY()
public:
    UPROPERTY(BlueprintReadOnly, Category = "Vital", ReplicatedUsing = OnRep_Health)
    FGameplayAttributeData Health;
    ATTRIBUTE_ACCESSORS(UMyAttributeSet, Health)   // 生成 GAMEPLAYATTRIBUTE_VALUE_GETTER 等

    UPROPERTY(BlueprintReadOnly, Category = "Vital", ReplicatedUsing = OnRep_MaxHealth)
    FGameplayAttributeData MaxHealth;
    ATTRIBUTE_ACCESSORS(UMyAttributeSet, MaxHealth)

    virtual void PreAttributeChange(const FGameplayAttribute& Attribute, float& NewValue) override;
    virtual void PostGameplayEffectExecute(const FGameplayEffectModCallbackData& Data) override;
    virtual void GetLifetimeReplicatedProps(TArray<FLifetimeProperty>& OutProps) const override;
};

ATTRIBUTE_ACCESSORS 宏会生成 GetHealthAttribute()、GetHealth()、SetHealth() 一整套样板，不要手写成裸 float 成员——那样就脱离了 GAS 的修改链路。

BaseValue 与 CurrentValue

这是 AttributeSet 里最关键、也最容易被忽略的区分：

字段含义
BaseValue永久值，由 Instant/Periodic GE 或 Setter 直接改
CurrentValue当前值，等于 BaseValue 加上所有 Duration/Infinite 修正（Buff）
Health: BaseValue = 100，被 +50 的持续 Buff 影响
→ CurrentValue = 150，BaseValue 仍是 100
→ Buff 到期后 CurrentValue 回到 100

绝大多数显示与判定都应该读 CurrentValue（即 GetHealth()）；只有"存档、升级、永久改变"才动 BaseValue。用错会表现为"Buff 消失了但效果还在"或"重连后 Buff 没了"。

关键回调

回调时机该做什么
PreAttributeChange任何值即将改变时钳制范围（Clamp），如 Health ∈ [0, MaxHealth]
PostAttributeChange值已改变后触发依赖该属性的逻辑（较少用）
PostGameplayEffectExecute一个 Instant/Periodic GE 执行完后伤害结算、死亡判定、触发事件
PreGameplayEffectExecuteGE 执行前修改 GE 的修正量（如伤害减免）
void UMyAttributeSet::PreAttributeChange(const FGameplayAttribute& Attribute, float& NewValue)
{
    Super::PreAttributeChange(Attribute, NewValue);
    if (Attribute == GetHealthAttribute())
        NewValue = FMath::Clamp(NewValue, 0.f, GetMaxHealth());   // 在这里钳制，而不是到处判断
}

void UMyAttributeSet::PostGameplayEffectExecute(const FGameplayEffectModCallbackData& Data)
{
    Super::PostGameplayEffectExecute(Data);
    if (Data.EvaluatedData.Attribute == GetHealthAttribute())
    {
        SetHealth(FMath::Clamp(GetHealth(), 0.f, GetMaxHealth()));
        if (GetHealth() <= 0.f) { /* 交由 Ability/ASC 处理死亡 */ }
    }
}

用 Meta Attribute 做伤害管线

Applied Damage 这类"无状态量"是 GAS 的经典套路——Meta Attribute：只在结算过程中存在，用完即弃。

1. GE_Damage (Instant) 修改 Damage 属性（Meta）
2. PostGameplayEffectExecute 里读到 Damage
3. 扣掉护甲、算上加成 → 得到最终伤害
4. 用另一个 Instant GE 扣 Health
5. Damage 属性重置为 0

好处是伤害的减免/加成/反射全都是 GE 的一环，可以被 Modifier、Tag、堆叠规则统一处理，不需要在代码里写公式。

网络复制

要点说明
GetLifetimeReplicatedProps必须注册，否则客户端收不到
OnRep_XXX必须调 GAMEPLAYATTRIBUTE_REPNOTIFY（宏），否则客户端不会跑回调链
REPNOTIFY_Always值没变也要触发（用于依赖 PreAttributeChange 的钳制）
只在服务端改客户端修改会被服务端覆盖，产生抖动
void UMyAttributeSet::OnRep_Health(const FGameplayAttributeData& OldHealth)
{
    GAMEPLAYATTRIBUTE_REPNOTIFY(UMyAttributeSet, Health, OldHealth);
}

漏掉 GAMEPLAYATTRIBUTE_REPNOTIFY 是最常见的"客户端属性不更新"原因。

与 ASC 的关系

事项说明
挂载AttributeSet 由 UAbilitySystemComponent 拥有，通常作为 Actor 的子对象创建
可以有多个按职责拆分（Vital / Combat / Resource）便于复用
全局查找ASC->GetSet<UMyAttributeSet>()
初始化用 GE（推荐，走完整链路）或 InitHealth() 系列直接设初值

设计建议

建议说明
按职责拆多个 Set一个巨大的 AttributeSet 会成为合并冲突中心
属性只放"数值"类别/状态用 FGameplayTag
所有修改都走 GE直接 SetHealth 会绕过 Modifier、Tag 与归因
钳制集中在 PreAttributeChange散落在业务里必然漏
区分资源型与统计型血量要复制，伤害统计可能只需服务端

常见坑

坑说明
把属性写成裸 float脱离 GE 链路，Buff 与复制全失效
混淆 Base/CurrentBuff 表现异常，存档数据错乱
忘记 ATTRIBUTE_ACCESSORS在 GE 里选不到这个属性
漏写 GAMEPLAYATTRIBUTE_REPNOTIFY客户端数值不刷新
在 PostGameplayEffectExecute 里又改同一个属性可能递归，要小心触发链
用属性表达状态比如 IsStunned 做成 0/1，应该用 Tag
Meta 属性忘记清零下一次伤害计算会叠加脏值
