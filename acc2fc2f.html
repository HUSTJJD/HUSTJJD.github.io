Computer Network

Base Knowledge, Computer Network 2025-08-10 2026-10-10 1489 字

自动关联目录：Computer Network

计算机网络回答的核心问题是：两个进程如何在一堆不可靠、有延迟、会丢包、会乱序的物理链路上，可靠地交换数据。

这个问题被拆成了分层结构。分层的价值不在于"整洁"，而在于每层只需要对上层提供一种新的保证，而不用关心下层怎么实现：

层给上层提供的新保证典型实现
应用层具体业务的语义（取网页、发邮件、解析域名）HTTP、DNS、SMTP
传输层端到端的进程到进程交付（+可选可靠/按序）TCP、UDP、QUIC
网络层主机到主机的跨网络路由，全局可达IP、ICMP、BGP/OSPF
链路层相邻两点之间的帧传输Ethernet、WiFi、PPP
物理层比特流在介质上的表示光纤、双绞线、无线电

为什么是分层

分层 = 逐级增强的抽象。每一层都在下层的服务上加一点东西：

链路层: 我把帧从 A 送到"下一跳" B（可能丢、可能错，但我会校验）
网络层: 我把包从源主机送到目的主机，中间经过若干跳（仍可能丢/乱序）
传输层: 我把字节流从源进程送到目的进程，且保证不丢、不重、按序
应用层: 我定义这些字节是什么意思

注意可靠性是在传输层补的，不是网络层。IP 是"尽力而为（best effort）"的，丢包不管。TCP 在 IP 之上用确认 + 重传 + 排序把不可靠变成可靠。这个设计叫 端到端原则（end-to-end argument）：能由端系统实现的功能，就不要放进网络核心——因为核心要为所有应用服务，做特化会拖累所有人。

封装：数据是怎么被层层打包的

应用数据
  │
  ├─ + HTTP 头   ──► HTTP 报文
  ├─ + TCP 头    ──► TCP 段（Segment）
  ├─ + IP 头     ──► IP 数据报（Datagram）
  ├─ + 以太网头/尾 ─► 以太网帧（Frame）
  └─ 物理信号

每一层只认识自己的头，对上层的数据一无所知（也不该关心）。解封装是逆过程。

MTU（Maximum Transmission Unit） 是链路层一次能承载的最大负载（以太网通常 1500 字节）。IP 包超过 MTU 就要分片，UDP 不分片就会丢，TCP 靠 MSS（= MTU - IP头 - TCP头，通常 1460）从源头避免分片。

两个模型

OSI 七层TCP/IP 四层对应协议
应用层HTTP, DNS, SMTP
表示层应用层TLS, JPEG, JSON
会话层(很少独立实现)
传输层传输层TCP, UDP
网络层网际层IP, ICMP
数据链路层链路层Ethernet, WiFi
物理层(TCP/IP 不定义)

OSI 是先有模型后有协议（理论先行，实现时一堆问题），TCP/IP 是先有协议后总结模型（实用主义）。结果是 OSI 模型赢了教学，TCP/IP 赢了世界。实际谈论时用"五层混合模型"最方便。

延迟：四个来源

总延迟=dproc+dqueue+dtrans+dprop\text{总延迟} = d_{proc} + d_{queue} + d_{trans} + d_{prop}总延迟=dproc​+dqueue​+dtrans​+dprop​

项含义量级
处理延迟dprocd_{proc}dproc​检查头部、查路由表μs\mu sμs 级
排队延迟dqueued_{queue}dqueue​在路由器队列里等变化最大，拥塞时可达秒级
传输延迟dtransd_{trans}dtrans​把LLL bit 推到链路上，L/RL/RL/R由带宽决定
传播延迟dpropd_{prop}dprop​信号在介质里跑d/sd/sd/s由距离决定，光纤约 5μs\mu sμs/km

区分传输延迟和传播延迟是理解网络性能的关键：

  • 传输延迟 = "车队过收费站的时间"（取决于车队长短和车道数）
  • 传播延迟 = "车在高速上跑的时间"（取决于距离和限速）

跨太平洋光缆单程约 60~80 ms，这是光速决定的下限，加带宽也没用。所以做全球化服务必须考虑地理部署，改善不了物理定律。

吞吐 vs 带宽

  • 带宽：链路的最大速率（bit/s），是能力
  • 吞吐：实际每秒传了多少，是结果

瓶颈链路决定端到端吞吐：throughput=min⁡iRi\text{throughput} = \min_i R_ithroughput=mini​Ri​。
