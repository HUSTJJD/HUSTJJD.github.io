Asset&Pak&Patch

Unreal Engine, Asset&Pak&Patch 2025-08-10 2026-10-10 954 字

自动关联目录：Asset&Pak&Patch

这一分支回答的是"资源从磁盘到内存、再到玩家机器上更新的全过程"。它是 Core（序列化、UObject）的下游，也是热更新、包体、加载卡顿这三个线上高频问题的交汇点。

一句话定位：资产不是文件，是被引擎索引、可被引用、可被切块、可被覆盖的一组对象。把这四层想清楚，这一分支就没有黑盒了。

本目录

笔记内容状态
AssetManager 与 PrimaryAsset资产标识、注册表、Bundle 与分块规则已补充
资源加载与异步加载同步/异步加载、软引用、保活、卡顿排查已补充
Cook 与打包流程Cook、DDC、平台差异、Chunk 划分已补充
Pak 与 IoStore容器格式、挂载顺序、签名与加密已补充
热更新与补丁差分补丁、版本管理、失败回滚已补充

四层结构

1. 标识层   FPrimaryAssetId（Type:Name） / FSoftObjectPath
2. 索引层   Asset Registry（不加载就能查询资产元数据）
3. 加载层   StreamableManager / 异步加载线程 → UObject
4. 容器层   Pak / IoStore（.pak、.utoc + .ucas）→ 挂载与覆盖

大多数"加载相关"的问题，其实出在第 1、2 层：标识写错了、注册表里查不到，后面的加载再怎么调都没用。

阅读顺序与优先级

顺序笔记什么时候读
1AssetManager 与 PrimaryAsset要组织资产、做分块、做按需加载时
2资源加载与异步加载遇到加载卡顿必读
3Cook 与打包流程第一次出包或包体异常时
4Pak 与 IoStore要控制打包结构、做加密时
5热更新与补丁上线前

如果只有一个问题要查：加载慢 → 第 2 篇；包体大 → 第 3 篇；更新失败 → 第 5 篇。

贯穿全局的三条线索

线索出现在
引用链（谁引用谁，决定打不打进包）AssetManager、Cook
时机（什么时候加载，决定卡不卡）异步加载、Pak 挂载
覆盖（新包如何盖住旧包）Pak 顺序、热更新

与其他分支的关系

Core / 序列化（资产是序列化后的 UObject）
        │
        ▼
Asset&Pak&Patch（索引 → 加载 → 容器 → 更新）
        │
        ├──► Profile / 包体与内存（SizeMap、memreport）
        ├──► Platform（平台差异、OBB、渠道要求）
        └──► GamePlay / Replication（资源引用与网络无关，但常一起踩）

排查入口

现象先查
加载卡顿/掉帧资源加载与异步加载，stat streaming
包体过大Cook 与打包流程，SizeMap
打包后资源丢失Cook 的引用链、PrimaryAssetLabel 配置
更新后资源没变Pak 与 IoStore 挂载顺序
补丁失败/版本错乱热更新与补丁 版本校验
