7 State

Programing, Design Pattern, 3 Behavioral 2025-08-10 2026-10-10 1538 字

自动关联目录：7 State

状态模式把"与状态相关的行为"各自封装进一个状态对象，状态切换时换掉这个对象，对外接口保持不变。

目的是消灭 switch (state)：把散布在十几个方法里的状态判断，收敛成"当前状态对象是谁"这一件事。

结构

角色职责
Context持有一个 State，把请求转发给它
State状态接口
ConcreteState实现该状态下的行为，并决定迁移到哪个状态

原笔记里的写法（状态迁移由各状态自己决定，Processor保持稳定）：

class AbstractState {
protected:
	AbstractState* m_Next;
public:
	virtual void DoSomething() = 0;
	virtual ~AbstractState() {}
	AbstractState* GetNextState() { return m_Next; }
};

class StateA : public AbstractState {
private:
	static AbstractState* m_Instance;
public:
	static AbstractState* GetInstance();
	virtual void DoSomething() override {
		m_Next->DoSomething();
		//状态切换，这部分是变化的。由各个子类自己实现。
		m_Next = StateB::GetInstance();
	}
};

class StateB : public AbstractState {
private:
	static AbstractState* m_Instance;
public:
	static AbstractState* GetInstance();
	virtual void DoSomething() override {
		//
		m_Next->DoSomething();
	}
};

class Processor {
private:
	AbstractState* m_State;
public:
	Processor(AbstractState* state) : m_State(state) {}
	// 状态增加时，这部分是稳定的。
	void DoSomething() {
		m_State->DoSomething();
		m_State = m_State->GetNextState();
	}
};

与 if-else 的对比

switch 版本状态模式
加一个状态改所有方法里的 switch加一个类
状态相关逻辑散落各处集中在一个类里
迁移规则混在业务逻辑里显式写在状态类里
代价——类变多，简单状态机是过度设计

只有 2~3 个状态且逻辑简单时，switch 更清楚。 状态模式的收益随状态数与行为数增长。

状态放哪：状态对象 vs 状态机

方案说明
状态对象（本模式）每个状态一个类，行为即方法，适合行为差异大
状态机表迁移表 + 进入/退出回调，适合状态多、迁移复杂、要可视化
分层状态机（HSM）状态可嵌套，处理"大多数状态共有的行为"
行为树不是状态机，但常用于替代复杂状态逻辑

原笔记的版本是"状态对象 + 状态自决定迁移"。另一种常见做法是迁移表集中在 Context/状态机里，状态对象只管进入/退出/更新：

  • 迁移规则集中 → 状态机的整体行为好读、好画成图
  • 迁移规则分散在状态里 → 加状态时改动更局部

状态迁移复杂时（10+ 状态），倾向于显式的迁移表。

工程要点

要点说明
进入/退出动作Enter() / Exit() 是最容易漏的，资源申请与释放都在这
状态对象是否共享无状态的状态对象可以做单例（原笔记的 GetInstance()），省分配
上下文传递状态需要访问 Context，构造时传入或作为参数传入方法
重入状态切换发生在回调中间时，要小心正在执行的代码
可观测性打状态迁移日志，否则"为什么进这个状态"极难查

与 Strategy 的区别

类图完全一样，区别在意图：

StateStrategy
谁决定切换对象内部随状态流转客户端主动选择
客户端是否感知不感知感知
状态之间是否互相知道通常知道，会互相迁移互相独立

常见坑

坑说明
忘了 Exit() 清理定时器、注册的事件没撤销，越跑越乱
状态对象持有大量状态数据应该在 Context 里，状态对象只管行为
状态爆炸状态数失控时应考虑分层状态机或行为树
迁移藏在条件分支里又变回 switch，只是搬了个地方
同一帧内多次迁移顺序不确定导致行为不一致，可改为下一帧生效

与引擎的对应

引擎机制对应
动画状态机（UAnimInstance）显式状态机 + 迁移条件
AI 行为状态 /黑板 + 行为树状态逻辑的替代方案
GAS 的 UGameplayAbility 生命周期激活/进行中/结束的状态流转
网络连接状态机典型的状态对象场景
