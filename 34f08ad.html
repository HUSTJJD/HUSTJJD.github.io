3 Lua GC

Programing, Lua 2025-08-10 2026-10-10 1079 字

自动关联目录：3 Lua GC

Lua 的 GC 是自动的、增量的、追踪式的。理解它有两层意义：一是知道对象什么时候会被回收（写宿主交互时关系到 userdata 的生命周期），二是知道卡顿从哪来——GC 是 Lua 项目里最典型的帧率毛刺来源。

算法：三色标记清除

经典的三色抽象：

颜色含义
白未访问，可能是垃圾
灰已访问，但其引用的对象还没扫完
黑已访问且引用都已扫描，确定存活
初始：全部为白
1. 从根集合（_G、注册表、栈、upvalue）出发，置灰
2. 反复：取一个灰对象 → 扫描其引用（白变灰）→ 自身变黑
3. 灰集合为空 → 所有白对象即为垃圾，清除

增量的含义：第 2 步被切成很多小片，每片之间把控制权交还给程序，避免一次性暂停。

增量带来的问题：标记过程中程序还在改引用关系，可能把黑对象指向白对象，导致白对象被误回收。Lua 用**写屏障（write barrier）**解决：

  • 前进（forward）：白对象被黑对象引用时，立刻标灰
  • 后退（backward）：把黑对象退回灰色，重新扫描

分代 GC（5.4）

5.4 引入分代模式作为可选项：

  • 假设"大多数对象很快就死"，所以频繁只回收年轻代
  • 老对象用独立的"触碰"机制处理，避免每次全量扫描
  • 分代模式跑一段时间后会自动触发一次完整 GC，防止老年代无限膨胀

用 collectgarbage("generational") / ("incremental") 切换。实际项目里：

场景建议
大量短命临时对象（战斗、每帧计算）分代
长期运行、对象集稳定增量（默认）更可预测

弱表

弱表是"引用不计入存活"的表，由元表里的 __mode 控制：

setmetatable(cache, { __mode = "k" })  -- 键弱引用
setmetatable(cache, { __mode = "v" })  -- 值弱引用
setmetatable(cache, { __mode = "kv" }) -- 都弱

典型用途：

用途做法
缓存值弱引用：没人用就自动消失
给对象挂扩展属性键弱引用：对象回收后条目自动清理
记忆化不延长参数生命周期

记忆口诀：弱表让"从表到对象"的引用不算数，从而不会阻止对象被回收。

手动控制

collectgarbage("collect")   -- 完整一次
collectgarbage("step", n)   -- 步进
collectgarbage("count")     -- 当前占用（KB）
collectgarbage("stop") / ("restart")
collectgarbage("setpause", 100)      -- 间隔：越大越懒
collectgarbage("setstepmul", 100)    -- 每步工作量：越大越快回收

工程上最常用的组合不是全量控制，而是两条：

  1. 在合适的时机手动全量回收——比如关卡切换、加载界面、过场动画，玩家感知不到
  2. 减少分配——这才是根本。每帧产生垃圾，再怎么调参数都是治标

卡顿排查

现象排查方向
周期性帧率毛刺GC 步进；用 count 打点看内存锯齿
内存只涨不跌有强引用被持有（全局表、闭包捕获、C 侧注册表）
userdata 不释放__gc 没实现，或宿主侧引用没断
弱表条目不消失引用方向搞反了（__mode 设错）

与宿主交互的注意点

  • C 侧持有的 Lua 对象必须放进注册表或 upvalue，否则会被回收
  • userdata 的 __gc 只在完全 userdata 上有效，轻量 userdata 没有
  • 不要在 __gc 里做复杂操作（此时 VM 状态受限），建议只做资源释放
