Base Knowledge, Computer Network 2025-08-10 2026-10-10 3756 字

链路层的职责

网络层负责"主机到主机"，链路层负责"一跳之内，相邻两点之间"。

具体提供：

  • 成帧（Framing）：把网络层数据报封装成帧，加上头尾
  • 介质访问控制（MAC）：多人共享一条链路时，谁先发
  • 差错检测：发现传输中的比特错误
  • 可靠交付（可选）：部分链路层提供重传，多数不提供

注意层次关系：IP 数据报在一路上内容基本不变，但每经过一跳，链路层帧头和帧尾全部重写（换 MAC 地址、换帧格式）。以太网 → PPP → 帧中继，帧格式可以完全不同。

成帧

三种方法

方法做法问题典型
字节计数帧头写长度长度字段出错就全乱早期 DDCMP
字节填充用特殊标志字节界定，数据里的标志字节用转义需逐字节扫描PPP
比特填充用 01111110 界定，数据里连续 5 个 1 后自动插 0硬件实现快HDLC、以太网前导

比特填充（bit stuffing）：发送方在数据里遇到连续 5 个 1 就插入一个 0，接收方遇到连续 5 个 1 后跟 0 就删掉这个 0。这样数据中永远不可能出现 01111110，可以用它做唯一界定符。

差错检测

链路层检错不纠错（纠错代价太高，直接重传更划算）。

奇偶校验

最简单：加一个校验位使 1 的个数为奇/偶。只能检出奇数个比特错误，两个比特同时翻转就漏检。块越大漏检率越高。

校验和（Checksum）

把所有字按反码加法累加，取反作为校验和。IP/TCP/UDP 都用它。

优点：软件实现快。 缺点：检错能力弱于 CRC（比如无法检出"两个字的对应位同时交换"这类错误）。

CRC（循环冗余校验）

链路层的标准做法（以太网用 CRC-32）。

原理：把数据当作多项式M(x)M(x)M(x) 的系数，双方约定生成多项式G(x)G(x)G(x)（r 阶）。发送方：

T(x)=xrM(x)+(xrM(x) mod G(x))T(x) = x^r M(x) + \big(x^r M(x) \bmod G(x)\big)T(x)=xrM(x)+(xrM(x)modG(x))

即在数据后补rrr 个 0，除以G(x)G(x)G(x)，把余数附在后面。接收方用T(x)T(x)T(x) 除以G(x)G(x)G(x)，余数为 0 则认为无错。

硬件上是移位寄存器 + 异或门，非常快。

CRC-32 的检错能力：

  • 检出所有单比特错误
  • 检出所有双比特错误
  • 检出所有奇数个比特错误
  • 检出所有长度 ≤ 32 的突发错误
  • 长度 > 32 的突发错误，漏检概率约2−322^{-32}2−32

多路访问协议

多个节点共享一条广播链路时，需要解决"谁说话"。

类型思路代表
信道划分静态切分，无冲突TDMA、FDMA、CDMA
随机接入想发就发，冲突了再处理ALOHA、CSMA/CD、CSMA/CA
轮流依次获得发言权轮询、令牌环

CSMA/CD（以太网有线）

Carrier Sense Multiple Access with Collision Detection

1. 载波监听：线路忙就等
2. 空闲则发送
3. 发送中持续检测冲突
4. 检测到冲突 → 立即停止，发阻塞信号
5. 二进制指数退避：从 {0,1,...,2^k-1} 随机选，k = 重传次数（k ≤ 10）
6. 重传（最多 16 次后放弃）

为什么需要冲突检测：因为传播延迟存在。A 发数据，还没传到 B，B 以为线路空闲也发了 → 冲突。A 要等 2×传播延迟才能确定没冲突。

二进制指数退避：冲突越多，随机窗口越大，降低再次冲突概率。这是以太网能在负载下保持稳定的关键。

最小帧长：以太网 64 字节。为什么要最小？因为要保证发送方能检测到冲突——如果帧太短，发完了才发生冲突，发送方已经"以为成功了"。64 字节对应 10 Mbps 下的 51.2 μs，正好覆盖最大往返传播延迟。

CSMA/CA（WiFi）

CA = Collision Avoidance，无线不能做 CD：

  • 无线是半双工的，发送时无法同时监听
  • 隐蔽站问题：A 和 C 都听不到对方，但都能到 B → 在 B 处冲突
  • 信号衰减：发送方自己的信号远强于远端，听不到冲突

所以 WiFi 用避免而非检测：

1. 监听信道（DIFS 时间）
2. 空闲 → 再随机退避一段（争用窗口）
3. 发 RTS（Request to Send）    ← 可选，解决隐蔽站
4. 收 CTS（Clear to Send）      ← 可选
5. 发数据
6. 收 ACK（必须！无线丢包率高）

没有 ACK 就当丢了重传——WiFi 在链路层就做重传，这是和以太网的关键区别。

以太网（Ethernet）

MAC 地址

48 bit，写成 00:1A:2B:3C:4D:5E。

  • 前 24 bit：OUI，厂商标识（IEEE 分配）
  • 后 24 bit：厂商自己分配，网卡唯一

特殊地址：

  • ff:ff:ff:ff:ff:ff：广播
  • 第 8 bit（从高位数第一个字节的最低位）为 1：组播

MAC 地址可以被软件修改（ifconfig ether），所以不能作为安全依据。

以太网帧格式（Ethernet II）

┌──────────┬──────────┬────────┬──────────┬──────┐
│ 前导(8B) │ 目的MAC(6)│源MAC(6)│ 类型(2)  │ 数据 │ CRC(4)│
└──────────┴──────────┴────────┴──────────┴──────┘
  • 前导：8 字节 10101010... 用于时钟同步，最后 1 字节是帧开始定界符。通常不计入"帧长"
  • 类型：0x0800=IPv4、0x0806=ARP、0x86DD=IPv6、0x8100=VLAN
  • 数据：46~1500 字节（不足 46 要填充，保证最小帧长 64）
  • CRC：4 字节，只有尾部有校验，没有帧头校验

MTU = 1500：指的是数据字段最大 1500 字节。加上 14 字节头 + 4 字节 CRC = 1518 字节帧。

巨型帧（Jumbo Frame）：9000 字节，数据中心内部常用，减少每包的固定开销和中断次数。

以太网演进

时代速率拓扑介质
1980s10 Mbps总线（同轴）同轴电缆
1990s10/100 Mbps集线器（Hub）星型双绞线
2000s1 Gbps交换机（Switch）双绞线/光纤
现在10/25/40/100/400 Gbps全交换光纤

关键转折是从共享介质到交换机：Hub 时代所有端口在一个冲突域（半双工，用 CSMA/CD），交换机时代每个端口独立冲突域（全双工，不再需要 CSMA/CD）。

ARP（地址解析协议）

IP → MAC 的映射。

主机 A (192.168.1.100) 要和 192.168.1.1 通信，但不知道它的 MAC

1. A 广播 ARP Request:  "谁是 192.168.1.1？告诉 192.168.1.100"
   （帧目的 MAC = ff:ff:ff:ff:ff:ff）
2. 192.168.1.1 单播 ARP Reply: "我是，我的 MAC 是 aa:bb:cc:dd:ee:ff"
3. A 把映射写进 ARP 缓存（有 TTL，通常几分钟）
arp -a              # 查看 ARP 缓存
arp -d 192.168.1.1  # 删除某条
ip neigh show       # Linux 现代命令

同网段 vs 跨网段

关键：ARP 解析的是下一跳的 MAC，不是最终目的。

同网段 192.168.1.100 → 192.168.1.200：
   ARP 查 192.168.1.200 的 MAC，帧直接发给它

跨网段 192.168.1.100 → 8.8.8.8：
   ARP 查默认网关 192.168.1.1 的 MAC，帧发给网关
   IP 头里的目的 IP 始终是 8.8.8.8，但帧头目的 MAC 是网关的

每一跳都是这样：送到下一个路由器，层层转发。

代理 ARP 与 ARP 欺骗

  • 代理 ARP：路由器代答 ARP，让主机以为目标就在本地网段
  • ARP 欺骗：攻击者伪造 ARP Reply，声称自己是网关的 MAC → 流量被劫持（中间人攻击）。局域网里的经典攻击手段，因为 ARP 协议没有任何认证机制

防护：静态 ARP 绑定、交换机端口安全、网络层加密（HTTPS/SSH）。

交换机

自学习

交换机即插即用，不用配置。它维护一张 MAC 地址表（MAC → 端口）：

1. 收到帧 → 记录 (源 MAC, 入端口) 到表里
2. 查目的 MAC：
   - 表里有 → 只从对应端口转发出去（单播）
   - 表里没有 → 从所有其他端口泛洪（flood）
   - 目的 MAC 是广播 → 泛洪

表项有 老化时间（通常 300 秒），因为网络拓扑会变。

交换机 vs 集线器

Hub（集线器）Switch（交换机）
层次物理层（转发比特）链路层（处理帧）
转发无脑广播到所有端口按 MAC 表精确转发
冲突域所有端口一个每端口一个
双工只能半双工（CSMA/CD）全双工
带宽共享每端口独享

Hub 已经被淘汰，因为广播所有流量既浪费带宽又不安全。

交换机 vs 路由器

交换机路由器
依据MACIP
广播域不隔离（除非 VLAN）隔离
即插即用是否（要配 IP/路由）
典型位置接入层汇聚/核心、边界

生成树协议（STP）

为提高可靠性会布冗余链路，但冗余会形成环路——广播帧在环路里无限循环，瞬间打满带宽（广播风暴）。

STP（802.1D） 的做法：逻辑上阻塞部分端口，把有环拓扑变成无环的生成树。主链路断了再启用备份链路。

现代演进：RSTP（802.1w） 收敛更快；MSTP 支持按 VLAN 多生成树，实现负载均衡。

VLAN（虚拟局域网）

802.1Q。在帧头插入 4 字节 VLAN 标签（含 12 bit VLAN ID，1-4094）。

作用：

  • 隔离广播域：一个物理网络切成多个逻辑网络
  • 安全：不同部门互不可见
  • 灵活：改 VLAN 配置比搬机器方便
[目的MAC][源MAC][0x8100][VLAN标签][类型][数据][CRC]
                        ↑ 4 字节插入，帧长变为 1522

跨交换机的 VLAN 用 Trunk 端口承载多个 VLAN 的流量。

无线链路（WiFi / 802.11）

与以太网的关键差异

特性以太网WiFi
介质独占线缆共享广播信道
冲突处理CD（检测）CA（避免）
确认无（链路层不确认）必须有 ACK
误码率极低（10−1210^{-12}10−12）高（10−510^{-5}10−5），受干扰
移动性无支持
隐蔽站无有（RTS/CTS 缓解）

802.11 命名

标准频段最大速率俗称
802.11b2.4G11 Mbps—
802.11a/g5G / 2.4G54 Mbps—
802.11n2.4/5G600 MbpsWiFi 4
802.11ac5G6.9 GbpsWiFi 5
802.11ax2.4/5/6G9.6 GbpsWiFi 6
802.11be2.4/5/6G46 GbpsWiFi 7

2.4 GHz 只有 3 个互不重叠信道（1、6、11），这就是为什么公寓楼里 WiFi 互相干扰严重。5 GHz 信道多但穿墙差。

WiFi 的关联过程

1. 扫描：被动（听 Beacon）或主动（发 Probe Request）
2. 认证：开放系统或 WPA
3. 关联：加入 AP，获得关联 ID
4. DHCP：拿 IP（和普通以太网一样）

PPP（点到点协议）

用于点对点链路（拨号、专线、PPPoE）。

特点：

  • 一个发送方、一个接收方，不需要 MAC 地址
  • 无需多路访问，简单得多
  • 提供差错检测、链路配置（LCP）、网络层配置（NCP）

PPPoE（PPP over Ethernet）：家庭宽带常用，因为在以太网上复用 PPP 的认证/计费机制（运营商熟悉这套）。

MTU 与 MSS

以太网 MTU = 1500 字节（IP 数据报最大 1500）
TCP MSS    = 1500 - 20(IP头) - 20(TCP头) = 1460

常见场景的实际 MTU：

场景MTU说明
标准以太网1500—
PPPoE1492减 8 字节 PPPoE 头
VPN（IPsec）1400 左右加密头开销
巨型帧9000数据中心内部

MTU 不匹配的症状：小包通、大包卡；能 ping 通但网页打不开。用 ping -f -l <size>（Windows）或 ping -M do -s <size>（Linux）测试。

常见坑

  • 广播域认知错误：以为交换机隔离广播。只有路由器（或 VLAN）才隔离
  • MTU 与 PPPoE：家里宽带 MTU 是 1492，用默认 1500 会出问题，症状是部分网站打不开
  • ARP 缓存未更新：换了网卡/IP 后，缓存还是旧的，表现为"时通时不通"
  • Hub 接交换机造成环路：没开 STP 的话广播风暴几分钟打瘫整个局域网
  • WiFi 信道规划：2.4G 只用 1/6/11，相邻 AP 用同信道会互相拖慢
  • 帧长和 MTU 混淆：MTU 1500 指 IP 数据报长度，以太网帧实际是 1518 字节（含头和 CRC）
  • VLAN ID 0 和 4095：保留值，不能用
