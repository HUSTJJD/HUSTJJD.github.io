UObject

Unreal Engine, Core 2025-08-10 2026-10-10 1291 字

自动关联目录：UObject

UObject 是 UE 里几乎所有引擎对象的基类。它带来的不是"继承一个基类"这么简单，而是一整套运行时服务：反射、GC、序列化、网络复制、编辑器集成。

反射

反射信息由 UHT（Unreal Header Tool） 在编译前扫描头文件生成 *.generated.h 与 *.gen.cpp。

宏作用
UCLASS()类参与反射，可被蓝图继承、可被 GC
USTRUCT()结构体参与反射，可用于蓝图与复制
UPROPERTY()字段可被序列化、复制、编辑器显示、且计入 GC 引用
UFUNCTION()函数可被蓝图调用、可作为 RPC、可绑定到委托

常见说明符：

说明符含义
EditAnywhere / VisibleAnywhere编辑器可改 / 仅可见
BlueprintReadWrite / BlueprintReadOnly蓝图读写权限
Replicated / ReplicatedUsing=OnRep_X网络复制与回调
Transient不序列化
Instanced作为对象实例而非引用
Category="..."编辑器分组

没有 UPROPERTY() 的成员对引擎是"不存在"的：不会被 GC 追踪、不会序列化、不会复制。

GC

UE 的 GC 是追踪式、可达性分析，从"根集合"出发扫描引用链。

根集合（Root Set）
├── 被 AddToRoot 的对象
├── 被引擎持有的（World、GameInstance…）
└── 通过 UPROPERTY 引用链可达的对象
要点说明
判定依据从根出发是否可达
引用必须标 UPROPERTY裸指针不参与引用图
容器也支持TArray<UObject*> 作为 UPROPERTY 会被追踪
手动保活AddToRoot / RemoveFromRoot、TStrongObjectPtr
手动销毁MarkAsGarbage、Actor 用 Destroy()
强制回收CollectGarbage / TryCollectGarbage（有卡顿，慎在运行时调用）

经典崩溃：UObject* 存在非 UPROPERTY 成员里 → 被回收 → 访问野指针。判据是 IsValid()（UE5 里它同时检查非空与未被标记为垃圾）。

序列化

  • 对象的 UPROPERTY 字段会被自动序列化（存档、资源、复制）
  • 自定义序列化：Serialize(FArchive&)，但要自己处理版本
  • 版本兼容：FArchive 的 ArVer 与自定义 CustomVersion

命名与路径

概念说明
GetFName()对象名（FName，哈希后）
GetPathName()完整路径，如 /Game/Blueprints/BP_Test.BP_Test
StaticClass() / GetClass()类信息（UClass*）
GetOuter()外层对象（构成对象树）
FindObject / LoadObject / StaticLoadObject按路径查找/加载

对象树（Outer 链）决定了很多行为：包（Package）是序列化的单位，也是 GC 的一个作用域。

创建与销毁

方式适用
NewObject<T>(Outer)创建普通 UObject
CreateDefaultSubobject<T>只能在构造函数里创建默认子对象（组件）
SpawnActor<T>生成 Actor
ConstructObject / DuplicateObject高级用法
Destroy()Actor 销毁（延迟到下一次 GC 真正释放）

构造函数里只能用 CreateDefaultSubobject，因为此时对象处于"Class Default Object"的构造阶段，任何依赖 World 的操作都不合法——运行时逻辑要放到 BeginPlay。

CDO

每个 UCLASS 都有一个 Class Default Object（CDO）：类的一份默认实例，作为所有实例的"默认值来源"。

  • GetDefault<T>() 取 CDO
  • 构造函数里设的值就是 CDO 的值
  • 蓝图类的默认值覆盖 C++ 的 CDO

理解 CDO 能解释很多现象：为什么改了构造函数默认值，已有蓝图实例不一定跟着变；为什么 UPROPERTY 的默认值要写在构造函数而不是 BeginPlay。
